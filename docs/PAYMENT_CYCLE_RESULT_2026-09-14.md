## المطابقة والإصلاحات

| المجال | التغيير والتحقق |
|---|---|
| رسالة التسوية | التحقق من message Bundle، MessageHeader الأول، الحدث والوجهة والمرسل وfocus، هوية التسوية، status active، outcome complete، فترة التسوية والتواريخ والمبلغ SAR والحقول المطلوبة. |
| بنود التسوية | أزيل اشتراط request وresponse على جميع البنود لأنهما 0..1 في الملف الرسمي. أضيف فحص التاريخ والنوع والمبلغ وcomponent-payment. بقيت المكونات السالبة للرسوم مسموحة، كما في المثال الرسمي. |
| الاستقبال المتكرر | قفل بمعرف الأعمال قبل التخزين؛ إعادة استلام التسوية نفسها تُقبل دون مضاعفة البيانات. اختلاف المورد تحت المعرف نفسه يُرفض. |
| حفظ وربط البيانات | ربط المنشآت بمعرف الترخيص وحل مراجع موارد الرسالة، بدل تشابه الأسماء. ربط المطالبة بواسطة system/value الفعليين في الطلب المحفوظ. حفظ Identifier الخاص بالبند وpredecessor، وحفظ امتدادات مالية غير معروفة دون تصادم تحت other. |
| السحب | المحافظة على رسالة التسوية الأصلية داخل الأغلفة المتداخلة. اختيار المنشأة المهيأة بدل أول صف عشوائي. عدم إخفاء فشل حفظ التسوية في system poll. حفظ تبادل السحب في السجل الموجود. |
| إشعار الدفع | المرجع والمبلغ من التسوية الأصلية؛ لا يُخمن system ولا يستبدل business identifier بمعرف المورد. التحقق من المرسل ومن التاريخ والمبلغ والحالة. |
| paid وcleared | اختيار صريح؛ أزيل الانتقال التلقائي. الواجهة تطلب تأكيد استلام البنك والتاريخ والمرجع. الاستثناء الاصطناعي في أداة التشغيل يعمل داخل sandbox فقط، ولا يمرر عبر API الواجهة. |
| سجل الإرسال | جدول payment_notice_attempts يحفظ الطلب قبل النقل والرد والنتيجة. منع الإرسال المتزامن والمكرر، وعدم إعادة الإرسال آليًا عند timeout. النتيجة المجهولة تبقى unknown وتمنع محاولة أخرى حتى التحقق منها. |
| نتيجة الإشعار | يلزم نجاح HTTP ورد ok مرتبط بمعرف الرسالة ودون OperationOutcome error/fatal. لا يُساوى HTTP 200 بالقبول. |
| شاشة Payments المحلية | أزيل عرض مدفوعات وهمية عند فشل API. أُصلحت مطابقة أسماء حقول الإنشاء والتعديل ومعرفات UUID والمبالغ الصفرية والتحقق من المبالغ السالبة. هذه السجلات المحلية ليست إثبات إرسال إلى نفيس. |

هذه فحوص تنفيذية واختبارات مثبتة للمسارات أعلاه، وليست شهادة تحقق رسمية لكل قيود FHIR أو كل قواعد نفيس غير المنشورة. توجد ملاحظة في الملف المنشور: نص BV-00053 وتعبير FHIRPath فيه لا يقدمان صياغة واضحة متسقة لاتجاه مقارنة period.end وcreated؛ لم تُفرض قراءة تخمينية له على المعاملات التاريخية.
