# دليل وسم النصوص السريرية لتقييم المساعد (الإصدار 1)

الغرض: إنتاج بيانات يوسمها مختصون، لقياس دقة فهم السياق بشكل مستقل عن المطوّر. الوسوم إنجليزية كما يستخدمها النظام، والشرح بالعربية.

- **من يَسِم:** ممارسان سريريان مستقلان لكل نص على الأقل، ثم مُحكِّم ثالث للخلافات.
- **ممنوع على المطوّر** أن يَسِم مجموعة التحقق أو الاختبار أو يطّلع عليها.

## 1. البيانات والخصوصية

- تُستخدم نصوص مصرّح باستخدامها فقط، بعد موافقة مسؤول حماية البيانات، وتُحفظ داخل بيئة المستشفى.
- تُزال المعرفات المباشرة قبل الوسم: الاسم، والهوية، ورقم الملف، والهاتف. **لا تُعدَّل الصياغة السريرية نفسها**، لأن تعديلها يغيّر ما نقيسه.
- تُسجَّل لكل نص لغته (en / ar / mixed) وقسمه، ليُقاس كل منهما وحده.

## 2. الكيانات

| type | ما يُوسم | أمثلة |
|---|---|---|
| problem | مرض، عرض، علامة، تشخيص | diabetes, chest pain |
| medication | دواء أو مادة علاجية | metformin, insulin glargine |
| allergy | مادة ذُكرت كسبب حساسية | penicillin (في "allergic to penicillin") |
| procedure | إجراء أو عملية | appendectomy, colonoscopy |

يُوسم موضع الكيان كما ورد في النص بالضبط (start/end)، دون تصحيح الإملاء.

## 3. السمات

**assertion** — هل الكيان مثبت للموصوف؟

| الوسم | متى يُستخدم |
|---|---|
| present | مذكور كموجود ("has diabetes") |
| absent | منفي أو مستبعد ("no diabetes"، "PE ruled out") |
| possible | غير مؤكد ("suspected"، "r/o"، "cannot be ruled out") |
| conditional | مشروط أو افتراضي ("return if fever") |
| unknown | لا يمكن الحكم من النص نفسه |

**experiencer** — لمن الحالة؟ patient / family / other / unknown. عبارة "mother reports he has asthma" تُوسم patient، لأن الأم هنا مصدر المعلومة لا صاحبة الحالة.

**temporality** — متى؟

| الوسم | المعنى |
|---|---|
| current | حالي، بما فيه المرض المزمن المستمر ("diabetes since 2015") |
| historical | انتهى أو من التاريخ السابق ("s/p appendectomy"، "resolved") |
| future | مخطط ("scheduled for colonoscopy") |
| unknown | لا يمكن الحكم |

**medication_status** (للأدوية فقط):

| الوسم | المعنى |
|---|---|
| current | يتناوله حالياً |
| discontinued | موقوف أو معلّق ("held") |
| proposed | مقترح أو مخطط |
| historical | استُخدم سابقاً |
| unknown | لا يذكر النص حالته. **الذكر المجرد للدواء لا يعني أنه حالي** |

**dose / unit / route / frequency / duration:** تُكتب كما وردت في النص حرفياً. **لا تُكمل قيمة غير مكتوبة.** إذا ذُكر "500" بلا وحدة، تُوسم الجرعة 500 وتُترك الوحدة فارغة.

## 4. الخلافات والجودة

- يُحسب الاتفاق بين المُعلِّمين لكل سمة بـ`scripts/annotatorAgreement.js` (Cohen's kappa) قبل التحكيم.
- **لا تُحدَّد عتبة قبول هنا**؛ تحددها المستشفى مسبقاً. يُعاد التدريب على الدليل إذا كان الاتفاق منخفضاً.
- يوثّق المُحكِّم سبب كل قرار. الحالات التي لا يتفق عليها المختصون تبقى unknown، ولا تُفرض لها إجابة.

## 5. التقسيم والتجميد

1. تُحدد معايير النجاح لكل وظيفة وتُعتمد **قبل** التقسيم، في ملف criteria.json. المعايير تُكتب حسب خطورة كل وظيفة، وليست هدفاً عاماً مثل 99%.
2. التقسيم:
   ```
   node scripts/clinicalEvalSplit.js --in annotated.jsonl --out-dir eval-<date> --salt <نص> --criteria criteria.json
   ```
   ينتج dev وvalidation وtest، وmanifest.json فيه بصمة كل ملف وبصمة المعايير.
3. مجموعة التطوير (dev) لتحسين القواعد. مجموعة التحقق (validation) لاختيار الإعدادات. **مجموعة الاختبار (test) لا يراها أحد ولا تُستخدم للتعديل.**
4. التشغيل النهائي مرة واحدة بعد تجميد الكود:
   ```
   node scripts/evalClinicalContext.js --file eval-<date>/test.jsonl --split test --manifest eval-<date>/manifest.json --criteria criteria.json --held-out-confirmed
   ```
   الأداة ترفض التشغيل إذا تغيّر الملف أو المعايير بعد التقسيم. تسجّل كل تشغيل في test-runs.log، وتحذّر إذا شُغّلت المجموعة أكثر من مرة. يتضمن التقرير بصمة الكود المختبر، وهي نفسها التي يعرضها `/api/openmed/status` في النشر.
5. يُعرض لكل لغة وقسم: حجم العينة وفواصل الثقة. ولا تُعمَّم النتيجة على لغة أو قسم لم يُقَس.
