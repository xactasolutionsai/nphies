# المساعد السريري — تقرير المرحلة الأولى (2026-09-26)

النطاق المنفَّذ: **التجهيز للربط** دون تحميل أي نموذج. فهم السياق السريري للنص يعمل الآن كطبقة حتمية مستقلة عن النموذج. تستقبل هذه الطبقة مخرجات OpenMed عند تثبيته. أُضيفت صلاحيات الوصول لكل مريض، والمراجعة البشرية بإصدارات، وأداة للتقييم.

لم يُحمَّل أي نموذج، ولم يُفعَّل Ollama أو يُنقل، ولم يُرسل أي شيء إلى نفيس. لم تُعدَّل بيانات مرضى، وكل النصوص المستخدمة اصطناعية.

> **لا يُعد هذا النظام "ذكاءً اصطناعياً طبياً جاهزاً".** لم تُقَس دقته على نصوص المستشفى، ولم يوسم أي نص بواسطة مختصين. التشغيل السريري ممنوع قبل بوابات القبول في القسم 9.

## 4. نتائج التقييم وحدودها

**لا توجد بيانات موسومة من مختصين.** كل الوسوم وضعها المطوّر، والنصوص اصطناعية.

- **مجموعة التطوير** (30 نصاً، 83 سمة مقيّمة): عُدّلت القواعد بناءً عليها، ونتيجتها بعد التعديل 100%. **هذا الرقم لا يقدّر الأداء على نص جديد.**
- **مجموعة التحقق** (20 نصاً): كُتبت قبل تشغيلها وشُغّلت مرة واحدة قبل أي تعديل. هذه هي النتيجة الأقرب للاستقلال (الملف `validation-run1-before-fixes.txt`):

|---|---|---|---|---|
| assertion | 13/14 | 92.9% | 68.5–98.7% | |
| experiencer | 5/5 | 100% | 56.6–100% | عينة صغيرة جداً |
| temporality | 3/5 | 60% | 23.1–88.2% | |
| medication_status | 1/7 | 14.3% | 2.6–51.3% | 5 من الأخطاء "unknown" (امتناع آمن). **خطأ خطير واحد:** "stopped taking simvastatin" ظهر كدواء حالي |
| type (حساسية) | 0/1 | — | — | "Amoxicillin causes hives" لم يُكتشف كحساسية |
| الجرعة والوحدة والطريق والتكرار والمدة | 13/13 | — | — | |

بعد هذا التشغيل:

- أُصلح الخطأ الخطير وأُضيف كاختبار انحدار.
- أضيفت عبارات: quit وconsidering وto exclude وdue for.
- صارت حالة الدواء 4/7، والأخطاء المتبقية كلها "unknown" تطلب المراجعة.
- **هذه الأرقام بعد الإصلاح لم تعد مستقلة.**

القيود المعروفة:

- لا يُعرف "on metoprolol" في بداية الجملة كدواء حالي، فيُترك unknown.
- الحساسية بصيغة "X causes hives" لا تُكتشف.
- عبارة "treated…, now resolved" لا تُفهم كتاريخ سابق.
- الأخطاء الإملائية خارج القائمة المسجلة لا تُفهم.
- التعارض بين عبارتين مختلفتين للمرض نفسه (مثل "DM" و"diabetes") لا يُكتشف دون تطبيع.
- **استخراج الكيانات نفسه (NER) لم يُقَس هنا.**


## 6. التشغيل والمراقبة والاسترجاع

- **التشغيل:** `npm run migrate` (أو `npm run migrate-openmed`) يطبّق 071، وهو إضافي فقط. بعده يمنح المشرف التفويضات عبر `POST /api/clinical-ai-access`.
- **تنبيه تشغيلي:** بعد النشر **لن يرى أي مستخدم أي مريض في صفحة OpenMed** حتى يُمنح تفويضاً. هذا مقصود (أقل صلاحية).
- **المراقبة:** `/api/openmed/status` يعرض إصدار محرك السياق ونموذج الوصول. السجلات لا تحتوي نصاً سريرياً.
- **الاسترجاع:** إرجاع الكود يعيد السلوك السابق. الجدولان الجديدان لا يؤثران على أي جدول قائم، ويمكن تركهما أو حذفهما يدوياً بعد قرار الاحتفاظ.

## 7. التبعيات والتراخيص

- لا توجد تبعية npm أو Python جديدة.
- محرك السياق كود المشروع، ويطبّق نهجاً منشوراً (NegEx 2001 وConText 2009). القوائم مكتوبة للمشروع.
- نماذج OpenMed مرخصة Apache-2.0 كما في السابق، ولم تُحمَّل هنا.
- لا توجد مصطلحات مرخّصة مضمّنة، و`normalized` يبقى `null` بوضوح.
