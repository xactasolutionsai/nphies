# دليل تشغيل المساعد السريري (NAFES)

هذا الدليل لفريق تقنية المعلومات والمسؤول السريري عن التجربة. لا يحتوي أي كلمة مرور. تُحفظ الأسرار في إعدادات الخادم فقط.

## 1. الإعدادات

| المتغير | الافتراضي | المعنى |
|---|---|---|
| `CLINICAL_AI_REQUIRE_PILOT` | مفعّل | التحليل والملخص والصياغة لا تعمل إلا داخل تجربة أو توسع معتمد. قيمة `false` لبيئات الاختبار غير السريرية فقط |
| `CLINICAL_AI_GENERATION` | معطّل | لا تعمل الصياغة بالنموذج إلا بـ`on`، مع `AI_FEATURES_ENABLED=true` واعتماد ميزة "generation" في التجربة |
| `OPENMED_DATABASE_URL` | — | حساب قاعدة بيانات منفصل ضمن مجموعة `nafes_openmed`، بلا صلاحية كتابة على جداول التطبيق |
| `OPENMED_WORKERS`، `OPENMED_MAX_QUEUE`، `OPENMED_QUEUE_TIMEOUT_MS`، `OPENMED_TIMEOUT_MS`، `OPENMED_PRELOAD`، `OPENMED_TORCH_THREADS` | 1، 8، 30000، 120000، فارغ، 2 | عمّال النموذج والطابور والمهلة. تُحدَّد القيم من قياس `scripts/benchOpenmed.js` على العتاد الفعلي |
| `OPENMED_RATE_PER_MINUTE` | 20 | حد التشغيلات لكل مستخدم في الدقيقة، مشترك بين نسخ الخادم عبر قاعدة البيانات |
| `OPENMED_RATE_LIMIT_STORE` | `db` | قيمة `memory` لخادم واحد فقط |
| `CLINICAL_AI_ALERT_INTERVAL_MIN` | 0 (معطّل) | فحص التنبيهات دورياً |
| `CLINICAL_AI_ALERT_THRESHOLDS` | انظر `openmed/alerts.js` | حدود التنبيه بصيغة JSON، **يحددها المستشفى** |
| `BUILD_COMMIT` | — | رقم الـcommit يظهر مع بصمة النسخة |

## 2. النشر

1. خذ نسخة احتياطية من قاعدة البيانات.
2. شغّل `npm run migrate`. الترحيلات 071–075 كلها إضافية.
3. أعد تشغيل الخادم، ثم تحقق من بصمة النسخة. البصمة يجب أن تطابق بصمة تقرير التقييم؛ إن اختلفت فلن يعمل المساعد، وهذا مقصود.
   ```
   GET /api/clinical-pilot/build
   ```
4. جرّب صفحة OpenMed بحساب مشارك: يظهر شريط التجربة، ويعمل التحليل على نص اصطناعي.

## 3. التشغيل اليومي

- **صفحة Clinical Pilot:** التنبيهات المفتوحة، والبلاغات الخطيرة (تظهر أولاً)، ومؤشرات كل تجربة.
- **`/api/openmed/status`:** حالة العمّال والطابور والأزمنة، والبصمة، وأهلية المستخدم.
- **السجلات لا تحتوي نصاً سريرياً.** أي حاجة لرؤية النص تكون عبر الصفحة، بتفويض الوصول للمريض.

## 4. الحوادث

| الحالة | ما يحدث تلقائياً | المطلوب |
|---|---|---|
| بلاغ خطير | يتوقف المساعد لكل مشاركي التجربة | فرز البلاغ. إن كان إصلاحاً في الكود: نسخة جديدة، ثم تقييم، ثم تجربة جديدة. الاستئناف بسبب مسجّل |
| تعطل أو تعليق عامل النموذج | يُستبدل العامل ويفشل طلبه فقط | إن تكرر: تنبيه `worker_error_rate`. راجع الذاكرة والمهلة |
| امتلاء الطابور | رد 429 أو 503 للمستخدم | تنبيه `queue_rejections`. زِد العمّال بعد القياس، أو خفّف الاستخدام |
| النسخة المنشورة ليست المقيّمة | المساعد متوقف | أعد نشر النسخة المقيّمة، أو قيّم النسخة الجديدة |
| رفض متكرر لمسودات الصياغة | تنبيه `generation_rejection_rate` | أوقف ميزة "generation" (أغلق التجربة أو سجّل تجربة بلا الميزة)، وراجع النموذج |
| الحاجة لإيقاف فوري | — | زر "إيقاف مؤقت" في صفحة التجربة، أو `CLINICAL_AI_GENERATION=off` للصياغة فقط |

## 5. الاسترجاع

- **إرجاع الكود:** يعيد السلوك السابق. الجداول الإضافية لا تؤثر على بقية النظام.
- **إيقاف المساعد دون إرجاع:** إغلاق التجربة. بلا تجربة نشطة لا يعمل شيء.
- **استعادة البيانات:** من النسخة الاحتياطية. سجلات المساعد في مخططات `openmed_advisory` و`clinical_knowledge` و`clinical_pilot`.

## 6. الاحتفاظ بالبيانات

مدة الاحتفاظ **قرار المستشفى**، ولا توجد مدة افتراضية.

```
node scripts/clinicalAiRetention.js --days <N>                                   # عرض الأعداد فقط
node scripts/clinicalAiRetention.js --days <N> --apply --policy-ref "<مرجع السياسة>"
```

- يستبدل نص الملاحظة ومخرجات النموذج والملخصات والمسودات بعلامة حذف.
- يُبقي المعرّفات والتواريخ والقرارات وسجل المراجعات للتدقيق والمؤشرات.
- لا يحذف صفوفاً، ويعمل في معاملة واحدة.

## 7. تحسين القواعد

1. صدّر تصحيحات التجربة إلى مجموعة التطوير:
   ```
   node scripts/exportPilotCorrections.js --pilot <id> --out pilot-dev.jsonl --i-confirm-authorised-environment
   ```
2. عدّل القواعد، ثم تحقق على مجموعة التحقق.
3. قيّم مرة واحدة على مجموعة الاختبار المجمّدة (`scripts/evalClinicalContext.js --split test ...`).
4. انشر النسخة، وسجّل تجربة جديدة ببصمتها.
