# قائمة اختبار الـsandbox قبل دمج PR #1

تغيّر محتوى الرسائل المرسلة إلى NPHIES أو طريقة إرسالها في هذا الـPR، ولم يُختبر أي من ذلك على بيئة sandbox. القائمة الكاملة لتغييرات محتوى الرسائل في `backend/tests/fixtures/README.md`، وفيما يلي البنود التي يجب اختبارها قبل الدمج.

## قبل الاختبار

- [ ] `npm run migrate` (أو `--baseline` على قاعدة موجودة)
- [ ] كل مؤمِّن في جدول `insurers` له `nphies_id`، وكل مقدّم في `providers` له `nphies_id`، وإلا يرفض النظام الإرسال بخطأ 400
- [ ] أدخل الطبيب المعالج (الترخيص، والاسم، والتخصص) في طلبات الأنواع: المهني، والمؤسسي، والأسنان، والعيون

## البنود

| # | التغيير | ما يُختبر | النتيجة |
|---|---|---|---|
| 1 | لا إعادة إرسال تلقائية بعد انتهاء المهلة أو خطأ 5xx أو رد 200 يحمل خطأ (الموافقة، والمطالبة، والإلغاء، والدفعة) | طلب ناجح، ثم طلب ينتهي بانتهاء المهلة: يجب ألا يتكرر | |
| 2 | ترخيص المؤمِّن من `insurer.nphies_id` بدل `INS-FHIR` (المؤمِّن الدافع، ووجهة MessageHeader في الأهلية والإلغاء) | أهلية، وموافقة، وإلغاء لكل مؤمِّن | |
| 3 | الطبيب المعالج بدل `PRACT-xxxx` | موافقة مهنية، ومؤسسية، وأسنان، وعيون | |
| 4 | حذف القيم السريرية الافتراضية (العلامات الحيوية، والشكوى، ومدة الإقامة، والـtriage، وحالة الخروج، والنصوص الافتراضية) | طلب ببيانات كاملة، وطلب ينقصه حقل: يجب أن تظهر رسالة واضحة قبل الإرسال | |
| 5 | Location لمقدّم الخدمة، و`Claim.facility` يشير إلى `Location` | موافقة ومطالبة مهنية | |
| 6 | نظام معرّف الإلغاء وفحص الحالة ومراسلات المطالبة يطابق `Claim.identifier` المُرسل (`/authorization` أو `/claim`) | إلغاء موافقة، وإلغاء مطالبة، وفحص حالة، ومراسلة غير مطلوبة على مطالبة | |
| 7 | حذف `MessageHeader.response` من طلب فحص الحالة (تعليق قديم في الكود يربطه بالخطأ IC-00224) | فحص حالة مطالبة | |
| 8 | الأهلية: معرّفات UUID، و`created` بتاريخ الطلب، والتوقيت +03:00 | أهلية لمريض جديد ولمريض موجود | |
| 9 | نظام ICD-10-AM لتشخيص الموافقات (كان `icd-10`) | موافقة بتشخيص | |
| 10 | حدث رسائل المراسلة في الموافقات المتقدمة صار `communication` | مراسلة على موافقة متقدمة | |
| 11 | الدفعات: كل مطالبة داخل الدفعة تحمل معرّف الدفعة وفترتها | دفعة من مطالبتين | |
| 12 | حالة الخروج إلزامية مع تاريخ نهاية الزيارة في الطلب المؤسسي، ولا قيمة افتراضية | مطالبة مؤسسية لها تاريخ خروج | |

إذا فشل أي بند: سجّل رمز الخطأ ومسار الحقل كما يظهران في صفحة تفاصيل الطلب، ولا تُعِد الإرسال تخميناً.

## ما لم يتغير

رمز التخصص `08.00` ما زال يُرسل افتراضياً، كما طلب المالك.
