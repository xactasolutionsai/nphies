# OpenMed: التحقق والتكامل الاستشاري

## هوية المشروع والمصادر

المشروع المطابق للشعار والوصف في الصورة هو [maziyarpanahi/openmed](https://github.com/maziyarpanahi/openmed). جرى التحقق من رابط المستودع ومعلومات الحزمة عبر [PyPI](https://pypi.org/project/openmed/)، ومن ترخيص الإصدار [v2.3.0](https://github.com/maziyarpanahi/openmed/blob/v2.3.0/LICENSE). ثُبّت الإصدار `2.3.0` محلياً في بيئة Python منفصلة. مستوى اليقين في هوية المشروع والإصدار والترخيص: **عالٍ**.

تصف الصورة عدداً أقدم من النماذج وعبارة مطلقة عن عدم خروج البيانات. أما الوصف الحالي في المستودع وPyPI فيوضح أن التشغيل الأساسي محلي بعد توفير الملفات، وأن التنزيل والإضافات الاختيارية قد تستخدم الشبكة. لذلك لا تُعد الصورة إثباتاً لخصوصية كل إعداد أو لكل نموذج. لا يعتمد هذا التكامل على عدد النماذج أو ترتيب GitHub المتغير.

## القدرة المضافة وحدودها

أضيفت صفحة `/openmed` ضمن أدوات المنظومة، وواجهات محمية تحت `/api/openmed`. تشمل البحث عن مريض، قراءة تشخيص ومعلومات داعمة نصية من مطالبة أو موافقة مختارة، تحرير نسخة النص، التحليل المحلي، حفظ النص والنتائج، واسترجاع آخر 30 استشارة للمستخدم مع تسجيل المراجعة أو الاستبعاد.

| النموذج | الغرض الفعلي | اللغة المعلنة | الترخيص | المرجع المثبت |
|---|---|---|---|---|
| [PharmaDetect SuperMedical 125M](https://huggingface.co/OpenMed/OpenMed-NER-PharmaDetect-SuperMedical-125M) | استخراج أسماء مواد كيميائية وأدوية؛ تصنيف CHEM | الإنجليزية | Apache-2.0 | `e55dbc4f4ef3f45480e77f4e7b1f4a86a5d9203d` |
| [DiseaseDetect SuperMedical 125M](https://huggingface.co/OpenMed/OpenMed-NER-DiseaseDetect-SuperMedical-125M) | استخراج أسماء أمراض | الإنجليزية | Apache-2.0 | `4bc0d813620c59e4ff6daa48e0b1a4732d021d14` |

بطاقة نموذج الأدوية تعرض نتائج على مجموعة BC5CDR-Chem؛ هذه ليست قياساً على بيانات المنشأة. لا يفترض التكامل دقة مماثلة على جميع الملاحظات أو أنه يفهم النفي والتاريخ العائلي. درجة النموذج ليست احتمال إصابة المريض. استخراج اسم مادة لا يثبت وجود تداخل دوائي، ولا يقدم هذا المسار وصفة أو تشخيصاً أو محادثة توليدية. **الصلاحية السريرية لبيانات المنشأة غير مقاسة**.

رغم وجود قدرات متعددة اللغات وإزالة هوية في المكتبة، فإن النموذجين المختارين إنجليزيان؛ يُرفض النص العربي بدلاً من الإيحاء بدعم غير مختبر. إزالة الهوية ليست مفعلة في هذه الصفحة، والنص الأصلي محفوظ ضمن السجل الاستشاري. جرى اختيار هذه القدرة المحددة لتقديم نتائج قابلة للمراجعة دون إدخال استنتاجات توليدية غير موثقة.

## العزل عن نفيس

- لا تستورد الوحدة خدمات نفيس أو محولات FHIR أو الإرسال أو الاستطلاع، ولا تُسجّل مهاماً دورية. لا توجد نقطة نهاية لترحيل نتيجة الاستشارة إلى مطالبة.
- الإضافة المشتركة في الخلفية هي تسجيل المسار الجديد بعد التحقق من الدخول. في الواجهة أضيفت الصفحة ورابطها فقط.
- تستخدم الوحدة اتصال PostgreSQL منفصلاً محدوداً إلى قاعدة التطبيق نفسها. تمنح مجموعة `nafes_openmed` قراءة أعمدة محددة فقط من المرضى والمطالبات والموافقات والمعلومات الداعمة؛ الكتابة محصورة في مخطط `openmed_advisory`.
- تفحص الوحدة الصلاحيات الفعلية وترفض اتصالاً يستطيع الكتابة في جداول `public`، حتى لو كانت بيانات الاتصال تخص مدير النظام. لا تعود تلقائياً إلى اتصال التطبيق ذي الصلاحيات الأعلى.
- الترحيل `064_openmed_advisory.sql` إضافي. الروابط إلى المريض والمستخدم تحذف الاستشارات التابعة عند حذف أحدهما، حتى لا تمنع حذف السجلات الأصلية. لا يضيف الترحيل أعمدة أو يغير رسائل نفيس.
- النص المختار فقط يمر عبر stdin إلى عملية Python. لا تُورث لها كلمات مرور قاعدة البيانات أو رموز التطبيق أو مفاتيح المزود. تعمل بأعلام offline وتعطيل telemetry وحظر اتصالات sockets في Python. لا يوجد استدعاء سحابي أو تنزيل نماذج أثناء التحليل. هذه ضوابط برمجية؛ يمكن إضافة منع خروج الشبكة على مستوى نظام التشغيل في النشر.

## التثبيت والتشغيل

المتطلبات: Python 3.10+، Node وPostgreSQL وفق المشروع. اختُبر التنفيذ هنا على Windows وPython 3.12 وCPU. تختلف احتياجات الذاكرة والوقت حسب الجهاز. ملفات النموذجين كبيرة وتُنزّل مرة واحدة، ولا تدخل Git.

من جذر المشروع على Windows:

```powershell
python -m venv backend/.venv-openmed
backend/.venv-openmed/Scripts/python.exe -m pip install -r backend/openmed/requirements-lock.txt
backend/.venv-openmed/Scripts/python.exe backend/openmed/download_models.py
```

على Linux يكون مسار المفسر `backend/.venv-openmed/bin/python`. يمكن استخدام `requirements.txt` كحد أدنى يثبت إصدار OpenMed؛ ملف lock يسجل البيئة التي اختُبرت. يحتفظ التنزيل ببطاقات النماذج وترخيصها، ويستخدم مراجعات ثابتة في `models.json`.

1. اضبط إعداد اتصال قاعدة التطبيق المعتاد في `backend/.env` دون تغيير إعدادات نفيس. شغّل من `backend`: `npm run migrate-openmed` باستخدام حساب مخول لإنشاء المخطط والمجموعة ومنح الصلاحيات.
2. أنشئ حساب اتصال منفصلاً بكلمة مرور خاصة لدى مسؤول قاعدة البيانات، مثلاً:

```sql
CREATE ROLE nafes_openmed_app LOGIN PASSWORD 'REPLACE_WITH_PRIVATE_PASSWORD'
  NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION INHERIT;
GRANT nafes_openmed TO nafes_openmed_app;
```

3. أضف `OPENMED_DATABASE_URL` إلى إعدادات الخلفية وفق `backend/openmed/env.example`، مستخدماً الحساب الجديد وقاعدة التطبيق نفسها. لا تضع هذا العنوان في إعدادات الواجهة أو Git.
4. أعد تشغيل الخلفية وابنِ الواجهة بالأمر المعتاد، ثم افتح **OpenMed Advisory**. إن غاب الاتصال أو الترحيل أو النماذج تعرض الوحدة عدم الجاهزية؛ تبقى بقية مسارات التطبيق مستقلة.

لم تتوفر في مساحة العمل إعدادات اتصال قاعدة المنظومة الفعلية عند التنفيذ. لذلك جرى تطبيق الترحيل واختبار الدورة كاملة على قاعدة PostgreSQL منفصلة ببيانات اصطناعية؛ يلزم تطبيق خطوات الاتصال أعلاه على قاعدة التشغيل المقصودة. لا تُرسل كلمات المرور في المحادثة.

## التحقق القابل للتكرار

من `backend` شغّل `npm test`. لتفعيل الاختبارات الموسعة:

```powershell
$env:TEST_DATABASE_URL='postgresql://USER:PASSWORD@127.0.0.1:PORT/app_regression'
$env:TEST_OPENMED_DATABASE_URL=$env:TEST_DATABASE_URL
$env:TEST_OPENMED_REAL_MODELS='true'
npm test
```

استخدم قاعدة محلية مخصصة ينتهي اسمها بـ`_regression` وحساب اختبار مخول بإنشاء قواعد وأدوار؛ ينشئ اختبار OpenMed قاعدة عشوائية وحساباً مؤقتاً ويحذفهما عند الانتهاء. لا توجهه إلى الإنتاج. تشمل الأدلة:

- تحليل فعلي بنموذجي OpenMed على نص اصطناعي، واستخراج مرض في نهاية نص يتجاوز نافذة النموذج الواحدة.
- إنشاء السجل واسترجاعه ومراجعته، ومنع مستخدم آخر من قراءة أو تعديل الاستشارة.
- رفض الكتابة الفعلية بحساب الوحدة في الجداول الأصلية، ومقارنة محتوياتها قبل وبعد الدورة.
- رفض مراجع مصادر تخص مريضاً آخر والنص العربي والحقول غير المسموحة، وعدم حفظ نجاح وهمي عند فشل التحليل.
- اختبارات رسائل FHIR السابقة تثبت مطابقة 14 رسالة مرجعية، دون معاملات حية إلى نفيس.
- `npm run lint` و`npm run build` من `frontend`.

**مستوى اليقين:** عالٍ في نتائج هذه الاختبارات المحلية وعزل مسارات الكود؛ غير محسوم في أداء النموذج السريري على بيانات المنشأة أو إعدادات نشرها حتى اختبار قبولها. لم يُجر اختبار قبول حي مع نفيس ضمن هذه الإضافة.
