# Security remediation — 13 September 2026

Target: https://87.237.225.69. Active release: `/opt/nafes/releases/20260913-security`.

## Completed changes

- Disabled registration inside the application in production, covering case and trailing-slash variants that bypassed the previous exact Nginx location.
- Added application-level failed-login throttling and input validation, including bcrypt's 72-byte input limit. Existing account passwords were preserved.
- Applied `Cache-Control: no-store` to authenticated API responses and authentication routes.
- Bound the production API to localhost. PostgreSQL remains on localhost; the unused PostgreSQL 16 cluster is stopped and configured for manual startup, with its data retained.
- Preserved public SSH port 22 and Ubuntu key access. Disabled root/password/interactive SSH authentication, X11 and agent forwarding; retained local TCP forwarding. Enabled Fail2ban for repeated SSH failures.
- Restricted permissions on application configuration and backup directories.
- Updated vulnerable JavaScript packages and removed unused LangChain, SQLite and PDF-parser dependencies. SheetJS uses its official 0.20.3 distribution; qs is overridden to the patched 6.16 series. Updated jsPDF, React Router, Vite and its React plugin.
- Removed raw HTML rendering from the highlighted JSON component; data is rendered as React text.
- Added restrictive object, base-URI and framing policies and disabled browser camera, microphone and geolocation permissions.
- Updated the deployed Python packaging tools to pip 26.2.1 and setuptools 84.0.0.
- Ubuntu security updates completed successfully through `unattended-upgrade`; daily automatic security updates are enabled. The host requires a reboot to activate the installed kernel 6.8.0-139 (currently running 6.8.0-51). No reboot was performed.

## Verification

- 57 backend regression tests passed against a disposable database, including NPHIES golden-message tests and real offline OpenMed inference/isolation tests.
- Frontend production build and lint passed. Bundle-size warning remains a performance concern.
- Backend and frontend `npm audit` report zero known vulnerabilities, including development dependencies.
- Python audit reports no known vulnerabilities in assessed packages. It **skipped `torch 2.14.0+cpu`**, which it could not resolve through PyPI; this is an explicit coverage limitation.
- Production HTTPS login and 20 API checks passed. Synthetic OpenMed analysis, persistence, review and history passed; synthetic records were removed.
- All 56 imported source tables / 72,174 source rows matched the restoration verification, allowing the previously documented deployment administrator account.
- Deployed registration variants returned 403; unauthenticated clinical/contact/advisory endpoints returned 401 with no-store headers.
- Fresh SSH connection succeeded; port 22 remains listening and allowed by UFW. API 8001 and PostgreSQL 5433 bind to loopback.

## NPHIES and remaining limits

No NPHIES mapper, message schema, endpoint configuration or business database migration was changed in this security work. Regression tests passed, but no real NPHIES transaction was sent: production integration credentials/configuration have not been supplied, and scheduled polling remains disabled.

This is a remediation of confirmed findings, not a guarantee that the application has no vulnerabilities. The browser CSP is intentionally limited and is not a complete script-source policy. Kernel updates require a reboot to take effect; check the host update status before scheduling maintenance.
